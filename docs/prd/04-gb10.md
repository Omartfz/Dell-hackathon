**Sanity (first 5 minutes):**

## 3. What to INSTALL (runtime, not the product)

Install order. Do not start writing agent prompts until step 3 answers `hello`.

### 3.1 Local model (inference brain)

Download **on the GB10**. After Ollama exists (NemoClaw Express / `install-ollama`):

```bash
ollama pull qwen3.6:35b
ollama list
```

If that is too slow or fails: `ollama pull qwen3.5:9b`. Still local. Do not pull Claude. Do not copy weights from another PC.

**vLLM path (optional):** Express Install default on Spark is often `qwen3.6-35b-a3b-nvfp4` via managed vLLM. Use it **only if** Express succeeds and `nemoclaw … status` shows local inference. Do not fight NGC all morning if Ollama already works.

### 3.2 NemoClaw + OpenClaw + OpenShell

One installer on the GB10:

```bash
curl -fsSL https://www.nvidia.com/nemoclaw.sh | bash
```

If venue net is dead, retry `nemoclaw.sh` when it is back. Do not depend on another PC.

When prompted: accept third-party notice; **Express install = Y** if it selects **local** inference. If it wants a cloud provider, decline and onboard local:

```bash
# Pattern only — confirm flag names with `nemoclaw onboard --help` on the box
export NEMOCLAW_PROVIDER=install-ollama   # or ollama / install-vllm as docs say
export NEMOCLAW_MODEL=qwen3.6:35b
nemoclaw onboard
```

**Prove the stack before building SafeContext:**

```bash
source ~/.bashrc
nemoclaw my-assistant status
nemoclaw my-assistant connect    # or dashboard-url / openclaw tui as installed
```

Type `hello`. If the reply is local (no cloud API), **install of the required stack is done**.

OpenShell is the sandbox around OpenClaw. You do **not** implement OpenShell. You **policy** it later (phase 6 in [03-demo.md](./03-demo.md)) if onboarding left a sandbox you can inspect.

### 3.3 MongoDB

Required for the product (central SoR). On the GB10, Docker is enough:

```bash
docker run -d --name safecontext-mongo -p 27017:27017 mongo:7
```

Pin a tag that has `linux/arm64`. If `mongo:7` fails to pull, use the ARM64 tag the box already has or `mongodb/mongodb-community-server` — **verify `docker pull` architecture**.

**Done when:** `mongosh` (or Python) can insert and read a ping document.

### 3.4 Python app runtime

On the GB10 (ARM64 wheels):

| Package | Why |
|---|---|
| `pymongo` | F2 — Mongo |
| `pydantic` | spec JSON validation |
| `httpx` or `openai`-compatible client **to localhost Ollama/vLLM only** | planner + optional local preview |
| Streamlit **or** FastAPI + uvicorn | F1/F7 UI |
| `pytest` | `test_minimize.py` |

No `anthropic`, no `openai` cloud keys, no LangGraph, no sentence-transformers, no faiss in v1.

`python3 -m venv .venv && pip install -r requirements.txt`

### 3.5 Do **not** install

- Kubernetes, extra vector DBs, Redis, Nginx mesh
- Cloud LLM CLIs for the agent
- x86 Docker images
- A second orchestrator (LangGraph)

## 4. What to BUILD on the GB10 (the product)

This is the contest work. **Clone this repo on the GB10** and build here.

| Build item | Runs on GB10 | Done when |
|---|---|---|
| `seed.py` → Mongo | Acme / Globex / Umbrella + injection ticket | `get_customer_bundle(Acme)` returns fat JSON |
| `catalog.py` + `minimize()` + `metrics()` | Same process as tools | pytest green on Acme |
| Five OpenClaw **tools/skills** | Inside OpenClaw (or Python loop fallback) | Traces show `whoami` → `find_customer` → `get_customer_bundle` → `get_policy` → `submit_spec` |
| Planner prompt | Local Qwen only | Spec JSON validates; not `if task == churn` in Python |
| UI page | Browser **on the GB10** (or SSH tunnel to 127.0.0.1) | Copy payload + exposure numbers live |
| `flip_role.py` | Mongo write | Scenario 3 |
| OpenShell policy (if APIs exist) | Sandbox | Optional; Scenarios 1–3 must work without it |

**Fallback (legal, say it out loud):** if OpenClaw tool registration is unclear after reading **installed** docs, run the same Python agent loop on the GB10, still calling local Qwen. Required stack is installed; the skill wrap can follow. Do not stall Scenario 1 on YAML.

**Do not build on the GB10:** Claude client, embeddings pipeline, PDF parser, LangGraph graph.

## 6. Network & security on the box

| Traffic | Allowed? |
|---|---|
| GB10 → local Ollama/vLLM | Yes (planner + preview) |
| GB10 → Mongo on localhost | Yes |
| OpenClaw → `submit_spec` only as egress from the agent | Yes |
| Agent → Anthropic / OpenAI / `build.nvidia.com` chat | **No** (planner) |
| Human copies payload off-box into Claude | Product, not our process |

If OpenShell can allowlist destinations, allow only local inference + local Mongo. **Verify the real policy API after install.** Ticket injection must still fail because `tickets.bodies` never enter `minimize()` output — even if OpenShell is skipped.

## 7. Definition of done (GB10)

The machine is ready to **judge** when:

1. `nvidia-smi` shows GB10; inference process is local (Ollama or vLLM).  
2. OpenClaw answers `hello` without a cloud provider.  
3. Mongo holds seeded Northwind/Acme data.  
4. UI on the box: Scenario 1 produces a copy-ready payload + live metrics.  
5. Scenario 2 (different task) and 3 (role flip) change the payload.  
6. No planner call to Claude.  

Install without (4)(5) is not the project. Agent code that never ran on this GPU is not the demo.

## 8. Failure map

| Failure | What to do |
|---|---|
| Venue Wi-Fi, no `nemoclaw.sh` net | Retry when net is up; no other PC |
| `linux/amd64` image | Delete it; pull `--platform linux/arm64` |
| Express wants NGC/vLLM, login fails | Ollama + `ollama pull qwen3.6:35b` on this box |
| 35B pull too slow | `ollama pull qwen3.5:9b`; continue |
| OpenClaw skills unknown | Python loop + local Qwen; wrap later |
| Mongo image missing ARM64 | Any official ARM64 Mongo/Community image |
